# Repair the Documentation Experience

## Why

The README, generated reference and publication pipeline currently disagree about links, navigation and available content. Repair them in eight independently verified phases so newcomers can install and use the real product, and contributors can maintain accurate English and Spanish documentation.

## What Changes

- Generate the complete site configuration from one committed template; add canonical URLs, branding, accessible themes, sectioned navigation and a helpful localized error page.
- Publish existing benchmark and managed-sidecar prose without inventing capabilities or altering benchmark claims; generate charts only from approved committed evidence.
- Make reference cross-links clickable, add read-only coverage validation, and use existing authoring commands without allowing CI to conceal missing prose.
- Commit missing command stubs, author the ten priority pages, and then make strict coverage blocking.
- Edit the README in place for installation, requirements, live badges, linked feature groups and a contents list; preserve substantive content in sections or an appendix.
- Create reproducible real-command demos with complete cache invalidation, preserving older demos in a gallery.
- Finish Spanish publication rather than dropping it or silently substituting English.
- Add verified contribution, release, security and issue/PR guidance; explicitly defer API reference and documentation versioning.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `documentation-generation`: Extend generation, publication, authoring checks, localized content and site acceptance while retaining non-strict library fallback behavior.

## Impact

Future implementation affects documentation generators and validators, resource prose, README, site configuration/template, benchmark presentation tooling, demos, docs CI and repository guidance. This change creates planning artifacts only; it does not edit those implementation inputs or commit anything.

Application behavior, benchmark results, release-platform support and managed-plugin functionality are not expanded. No removal of user-facing content, Spanish withdrawal, benchmark claim change, extra README restructuring, or versioned-doc rollout is authorized. The eight phases proceed in order, each ending with recorded passing checks; local proof and deployed proof must be distinguished.
